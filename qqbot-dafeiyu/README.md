# 小小坤ovo · QQ 机器人

接在 **DeepSeek** 上，兼职当群管。

用的是 **普通 QQ 号**（不是 QQ 开放平台的官方机器人），通过 **NapCat** 协议端登录，
手机 QQ **扫码**即可上线，不需要 AppID / Secret / 公网回调。带一个 **Web 控制台**。

```
手机 QQ ←扫码→ NapCat（协议端，模拟客户端） ←WebSocket→ 本机器人 ←HTTPS→ DeepSeek
                                                          ↑
                                                    Web 控制台 :8899
```

## 能干什么

**AI 聊天**
- 群里 `@小小坤ovo 今天吃啥`、私聊直接说话、或者句子里带「小小坤ovo」都能触发
- 按群（私聊按人）独立上下文（默认记 8 轮，闲置 30 分钟自动忘）
- `深度 xxx` 走 `deepseek-reasoner` 认真想；`总结 30` 让 AI 把最近 30 条群消息划重点

**群管理**（需要机器人在群里是管理员）
- 禁言 / 解禁 / 全员禁言（自动到期解除）
- 踢人（可拉黑）/ 撤回（单条或最近 N 条）
- 群公告 / 改群名片 / 设头衔 / 设精华 / 改群名 / @全体
- 违禁词自动撤回 + 累计警告，警告满 N 次自动禁言
- 刷屏检测（N 秒内超过 M 条自动口球）
- 入群欢迎（支持 `{at}` `{name}` `{group}` 占位符）
- 入群申请推送给主人，`/同意` `/拒绝` 处理
- 入群验证（答对自动通过，答错不拒绝只通知主人）
- 黑名单 / 全局黑名单，命中自动拒绝入群
- 清理死人（先预览名单，加「确认」才真踢）
- 关键词自动回复、定时提醒、群活跃排行

**AI 内容哨兵**
- 本地粗筛 → DeepSeek 判定 → 分级处置（L2 撤回 / L3 禁言 / L4 踢出+拉黑）
- 一切判定可回溯，误封能 `/撤销` 翻案

**其它**
- 66 个命令、按权限自动过滤帮助菜单
- 配置热重载（`/重载`），改完不用重启
- 消息台账、对话日志、按天轮转的日志文件

## 快速开始

### 1. 装依赖 + 下载协议端

双击 **`install.bat`**，它会：
- 装 Python 依赖（aiohttp / websockets）
- 生成 `config.json`
- 下载 NapCat（约 120MB，走国内镜像，失败会自动换线路）

> 手动装也行：`pip install -r requirements.txt` 然后 `python tools/napcat_setup.py --download`

### 2. 填 DeepSeek API Key

打开 `config.json`，把这一行填上：

```json
"deepseek": {
  "api_key": "sk-你的key",
  ...
}
```

Key 在 <https://platform.deepseek.com/api_keys> 申请，`deepseek-chat` 很便宜，
日常群聊一个月通常几块钱。

### 3. 双击 `start.bat`，扫码

启动后会：
1. 自动补好 NapCat 的 OneBot 配置（WS 端口 3001）
2. 拉起 NapCat，弹出二维码图片
3. **用手机 QQ 扫码** → 确认登录
4. 机器人连上，控制台打印 `已连上 OneBot 端`

登录态会缓存在 NapCat 里，**下次启动不用再扫**。

> 二维码没自动弹？手动打开 `data/qrcode.png`，或访问 NapCat 的 WebUI
> <http://127.0.0.1:6099/webui>（默认 token 在 `napcat/config/webui.json` 里）。

## Web 控制台

机器人启动时会同时拉起一个网页控制台（跟机器人同一个进程，读的是内存里的实时状态）。

```
http://127.0.0.1:8899
```

首次启动会自动生成访问口令，写进 `config.json` 的 `webui.token`，启动横幅里也会打印。

**七个页签**

| 页签 | 能干什么 |
|---|---|
| 概览 | 在线状态、账号、运行时长、消息/命令/AI 调用数、token 消耗、会话数、所在群数；一键重载配置、清空上下文 |
| 群管理 | 群列表（人数/消息数/欢迎/违禁词/关键词），点一行展开：改欢迎语、开关欢迎、编辑违禁词、配关键词、**直接禁言/解禁/移出成员**、发测试消息 |
| 会话 | 列出所有对话上下文（哪个群、几轮、闲置多久、最后一句），可单条清空或全部清空 |
| 提醒 | 列出所有待发提醒（群号、内容、还有多久），可单条删除 |
| 统计 | 今日/累计消息、7 天消息量柱状图、命令使用排行、各群积分榜 |
| 配置 | 直接改 DeepSeek Key/模型/温度、人设、记忆轮数、冷却、接话模式、反刷屏阈值、主人 QQ —— 保存即生效 |
| 日志 | 实时 tail 运行日志 |

**安全**：默认只绑 `127.0.0.1`。这个控制台能改配置、能往群里发消息，**绝对不要直接暴露公网**。
要在自己电脑上访问，走 SSH 隧道：

```bash
ssh -L 8899:127.0.0.1:8899 root@<服务器>
# 然后浏览器打开 http://127.0.0.1:8899
```

Windows 上双击 `webui.bat` 会自动开隧道并打开浏览器。

改端口：`config.json` 里的 `webui.port`（换完要重启机器人）。想彻底关掉就把 `webui.enabled` 设成 `false`。

### AI 哨兵

用 DeepSeek 判断消息内容，判到阈值就自动处置。**默认只封 L4（极端内容）**。

| 命令 | 权限 | 说明 |
|---|---|---|
| `哨兵` | 管理员 | 看状态、阈值、累计统计 |
| `哨兵 开` / `哨兵 关` | 管理员 | 开关 |
| `哨兵 阈值 4` | 主人 | 判到几级直接封禁（1~4） |
| `哨兵 抽查 0.05` | 主人 | 随机抽查概率（0 = 只审命中嫌疑特征的） |
| `哨兵 记录` | 管理员 | 最近 10 条判定（谁、几级、做了什么、为什么） |
| `哨兵 测试 文本` | 管理员 | **只判定不处置** —— 调提示词时全靠它 |
| `撤销 [@某人]` | 群管 | 人工翻案：解黑 + 解禁 |

等级定义：

| 等级 | 含义 | 默认动作 |
|---|---|---|
| L0 | 正常（技术讨论、玩梗、吐槽都算） | 放行 |
| L1 | 轻微不当（轻度脏话、擦边玩笑） | 放行 |
| L2 | 明显不当（辱骂、广告引流、刷屏） | 撤回 + 警告 |
| L3 | 严重（色情、人身威胁、诈骗） | 撤回 + 禁言 10 分钟 |
| L4 | 极端（组织违法、暴恐、涉未成年、大规模诈骗） | **撤回 + 踢出 + 拉黑** |

**它怎么工作的**（两层，不是每条都问 AI）：

```
消息 → 本地粗筛（白名单/长度/关键词/结构特征）→ 可疑才送 DeepSeek → 按等级处置
```

本地粗筛挡掉 99% 的正常消息，所以 token 成本很低。命中嫌疑特征才送审，也可以配
`guard.sample_rate` 做随机抽查，覆盖「没命中关键词但确实有问题」的情况。

**四条安全阀**（都是「不这么做就会出事」的）：

1. **AI 不可靠时绝不封人**：Key 失效、超时、返回不是合法 JSON —— 一律只记录不执行
2. **把握不足只记录**：模型给的 `confidence` 低于 `guard.min_confidence`（默认 0.7），
   判到 L4 也只写进「待人工看」，不动手
3. **管理豁免**：主人 / 机器人管理员 / 群主 / 群管 默认不过审（`guard.exempt_admin`）
4. **命令不过审**：群管发 `/违禁词 添加 xxx` 时不会被自己的哨兵封掉

**全部判定写进 `data/guard.jsonl`**，控制台「哨兵」页能查，误封用 `撤销` 翻案。

## 权限模型

```
100  主人      config.permission.superusers —— 全部权限
 60  机器人管理  config.permission.admins    —— 跨群的管理命令
 50  群主      QQ 群里的群主
 40  群管      QQ 群里的管理员
 10  普通成员
```

两点容易踩：

1. **群管命令要求「机器人在群里是管理员」**，不是操作者是管理员就行。
   机器人被撤管理后会回「我在这个群不是管理员」。
2. 同级之间不能互相操作：管理员禁不了管理员，群主只有主人能动。

第一次用：私聊机器人发 `绑定主人`，就把自己设成主人了（仅限还没配置过主人的时候）。

## 配置说明

改完 `config.json` 后，主人发 `/重载` 即可生效（`onebot` 段的连接参数除外）。

| 字段 | 默认 | 说明 |
|---|---|---|
| `guard.enabled` | `true` | AI 内容哨兵开关 |
| `guard.ban_level` | `4` | 判到几级直接封禁（4 = 只有极端内容） |
| `guard.min_confidence` | `0.7` | 模型把握低于此值只记录，不动手 |
| `guard.sample_rate` | `0.0` | 随机抽查概率；0 = 只审命中嫌疑特征的 |
| `guard.exempt_admin` | `true` | 主人 / 管理 / 群主 / 群管免审 |
| `bot.prefixes` | `["/", "#"]` | 命令前缀 |
| `bot.group_trigger` | `all` | 群里什么时候接话，见下 |
| `bot.nickname_trigger` | `true` | at 模式下，消息里带昵称也触发对话 |
| `bot.reply_with_at` | `true` | 群里回复时 @ 提问的人 |
| `deepseek.model` | `deepseek-chat` | 日常模型 |
| `deepseek.reasoner_model` | `deepseek-reasoner` | `深度` 命令用的模型 |
| `deepseek.temperature` | `1.1` | 越高越飘 |
| `chat.context_rounds` | `8` | 每个会话记几轮 |
| `chat.context_ttl` | `1800` | 闲置多少秒后丢弃上下文 |
| `chat.group_cooldown` | `3` | 同一个人同群的对话冷却秒数 |
| `group.anti_spam` | 开 | `window` 秒内超过 `limit` 条判定刷屏 |
| `group.warn_mute_threshold` | `3` | 警告几次自动禁言 |
| `group.welcome_text` | 见文件 | 入群欢迎语模板 |

环境变量优先级最高，适合临时改：`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`QQBOT_WS_URL`、`QQBOT_TOKEN`。

### 群里什么时候接话

`bot.group_trigger` 四档：

| 值 | 行为 | 适合 |
|---|---|---|
| **`smart`（默认）** | `@` 必回；**像提问的才回**；其余按 `chat.smart_reply_probability`（默认 0.08） | 想让它像个正常群友，又不想被刷屏 |
| `at` | 只有 `@机器人` 或消息里出现昵称才接 | 群人多、想彻底省 token |
| `prob` | 按 `chat.group_reply_probability`（默认 0.35）随机接，@ 必回 | 想要点随机感 |
| `all` | 群里**所有消息都接** | 人很少的小群 |

**另外还有一道「说完就安静」**：机器人自己发过言之后，`chat.group_speak_cooldown`（默认 20 秒）内
不会再主动接话 —— `@` 不受这个限制。这条比概率更能治「太主动」，因为它管的是**节奏**，
不会让机器人在一句话里连追三句。

> 「像提问」的判据：带 `?` / `？`，或含 `吗 呢 怎么 为什么 什么 多少 哪里 哪个 谁 是不是 能不能 有没有 如何 咋 …`。
> 宁可漏判（少接一句），也不把陈述句当问题抢答。

⚠️ `all` 模式下群里每句话都会走一次 DeepSeek，人多时 token 烧得很快，也最容易显得像刷屏。

不管哪一档，命令（`/禁言` 之类）始终只认前缀，不会因为 `all` 模式就把日常聊天当成命令。

## 部署到服务器（Linux）

线上已经跑起来了，落在 `your-server.example.com`：

| 组件 | 位置 | 说明 |
|---|---|---|
| NapCat | Docker 容器 `napcat`（`mlikiowa/napcat-docker`） | 端口 `127.0.0.1:3001 -> 3001`，`restart=always` |
| 配置卷 | `/var/lib/docker/volumes/ea8765…/_data` | `onebot11.json` / `onebot11_<QQ>.json` |
| QQ 数据卷 | `/var/lib/docker/volumes/03c82d…/_data` | 登录态，删了就掉登录 |
| 机器人 | `/www/wwwroot/dafeiyu-bot`，pm2 名 `dafeiyu-bot` | venv 在 `.venv/` |
| 控制台 | `127.0.0.1:8899`（仅本地） | 本机 `webui.bat` 开隧道访问 |
| 运维脚本 | `/www/wwwroot/dafeiyu-bot/manage.sh` | 见下 |

```bash
cd /www/wwwroot/dafeiyu-bot
./manage.sh status     # 容器 / 机器人 / 端口 / 登录态
./manage.sh qr -r      # 换一张新二维码（重启 NapCat，约 2 分钟有效）
./manage.sh logs       # 机器人日志
./manage.sh fix        # 重写 OneBot WS 配置并重启 NapCat
```

**两个坑**：

1. NapCat 在容器里，宿主机上 `/root/Napcat/` 那套是**另一份装坏的**（`qq` 一跑就
   `Illegal instruction`）。改配置要改**容器卷**里的文件，改宿主机那份没用。
2. 容器原本是 `bridge` 网络且**没映射端口**，机器人连不进去。重建时必须带
   `-p 127.0.0.1:3001:3001`（只绑本地，别暴露到公网）。

重建命令（保留原卷，登录态不丢）：

```bash
docker rm -f napcat
docker run -d --name napcat --restart always \
  -p 127.0.0.1:3001:3001 \
  -v 03c82d4b2a715d00555898cf7230774222b1bb5d49de3127769f3c78cea98067:/app/.config/QQ \
  -v ea8765a338f9432dee0d3c3fe6522e8b942cfbd4fafce85420f5b3a6a2104884:/app/napcat/config \
  mlikiowa/napcat-docker
```

**注意**：NapCat 的 OneBot 配置**不会热加载**，改完必须重启容器。重启后 QQ 会掉登录，
需要重新扫码（除非 quick login 的 token 还有效）。

## 常见问题

**扫码后提示登录失败 / 需要验证**
QQ 风控。换手机热点、换个时间段，或者在手机上先正常登录该账号养几天。
新注册的小号最容易被拦。

**会不会封号？**
非官方协议登录**有风险**，这是所有第三方 QQ 机器人的共同前提。
建议：用小号、别做批量加群/发广告/秒回所有人这类明显的机器人行为、别挂太多群。
本项目默认加了对话冷却和刷屏保护，就是为了让它「像个人」。

**二维码不弹**
1. 看 `napcat/cache/qrcode.png` 在不在
2. 访问 <http://127.0.0.1:6099/webui>，token 在 `napcat/config/webui.json`
3. 实在不行手动跑 `napcat/launcher.bat`，二维码会打在它自己的控制台里

**机器人连不上 / 一直重连**
```bash
python tools/napcat_setup.py --check
```
确认 `napcat/config/onebot11_<QQ号>.json` 里有 `dafeiyu-ws` 这一项、端口 3001。
第一次扫码登录后才生成这个文件，所以**登录完要再跑一次 `start.bat`**（或 `--ensure`）把配置补进去。

**AI 不说话，只回「脑子卡住了」**
- 401：Key 错了
- 402：余额不足
- 429：限流，等一会儿

**群管命令没反应**
机器人得先是群管理员。而且 QQ 只允许操作**比自己权限低**的人。

**想让它更像个真人**
调 `chat.temperature`（1.2~1.4 更跳）、`chat.context_rounds`（记更多），
再改 `chat.system_prompt` 给它加口癖。
