# QQ 官方机器人：KunClient 账号服务 + 群管理

基于 **QQ 机器人开放平台官方 API**（`api.bot.qq.com`，WebSocket 网关直连，无第三方框架）的群机器人，
内置 **KunClient 账号绑定 / 积分签到** 和 **群管理工具**。

机器人：**KunClient Bot**（AppID 1905735603）

## 设计目标：不认识命令也能用

- **自然语言容错**：命令打错会提示「你是想发 xxx 吗」；全角字符自动转半角
- **分层帮助**：`帮助` 只列常用项，`帮助 更多` 出全量，`帮助 管理` / `帮助 kun` 看详解
- **权限显式**：四级角色 + 权限节点 + 目标保护 + 审计，授权可追溯
- **离线自测**：身份、权限、菜单、群管接口都能本地跑，不联网也能验证

## 权限体系（v3 重做）

> 旧设计只有「管理员/超级管理员」两档，且 QQ 群主/管理员会被平台**无条件自动提权**、
> 群管理员能拉黑超级管理员（权限倒挂）、授权与封禁不留记录、未绑定用户跨群封禁形同虚设。
> v3 重做为四级角色 + 权限节点 + 目标保护 + 审计的完整 RBAC。

### 角色（数值越高权限越大）

| 角色 | 等级 | 来源 | 能力 |
|---|---|---|---|
| `owner` 主人 | 100 | `config.json` 的 `owner_qq`（**可填多个**：字符串或数组） | 全部权限；**永不被封禁/降级/管理操作命中** |
| `super` 超级管理员 | 80 | `config.json` 的 `admins`，或主人发「超管添加」 | 全局封号 / 身份维护 / 群管授权 / 机器人管理 / 服务端管理 |
| `group_admin` 群管理员 | 40 | 超管及以上发「设置管理 @某人」（按群） | 本群：关键词 / 开关 / 公告 / 欢迎语 / 拉黑 / 积分管理 |
| `user` 普通用户 | 0 | 默认 | 签到 / KunClient 绑定 |

- 授权全部**显式、持久化**在 `data.json` 的 `roles` 表，可逐群授予、可撤销、可审计。
- **多主人**：`owner_qq` 支持两种写法——`"owner_qq": "12345678"`（单主人）或
  `"owner_qq": ["12345678", "87654321"]`（多主人）。多个主人平级，互相之间也不能
  封禁/降级（目标保护对所有主人一视同仁）。改完发「重载配置」即生效。
- **平台群主/管理员身份默认不再自动提权**。想要旧行为：`config.json` 设
  `"permissions": {"trust_platform_roles": true}`；且该行为可被逐群压过
  （「移除管理」会显式写成 `member` 降级标记）。
- 私聊（C2C）里群管理员身份不生效——群管权限本来就是按群的，合理隔离。

| `group.join` | 40 | 入群申请 / 入群同意 / 入群拒绝 |
| `group.grant` | 80 | 设置管理 / 移除管理 |
| `global.ban` | 80 | 封号 / 解封 / 封号列表 / 拉黑 全 / 取消拉黑 全 |

### 目标保护（防权限倒挂）

所有「针对人」的操作（拉黑 / 封号 / 授权 / 调积分）执行前过 `bot.guard_target`：

- **不能对主人执行任何管理操作**（封禁、授权、扣分都不行）；
- **不能对权限 >= 自己的成员执行**（同级互咬、群管封超管都被拒绝，操作者本人除外）；
- 未绑定的占位键身份等级为 `user`，正常放行。

### 全局封禁：按 QQ 号 + openid 兜底

- 查到 QQ 号 → 按号封，跨群跨私聊立刻生效，换群、换设备都不失效；
- 对方从没绑定 QQ 号 → 先把他的 **openid 加入兜底拦截**（`identity_ban`，所有已知身份场景生效）+ 封本群；
- 对方日后 `绑定QQ` 或被超管 `设QQ号` 登记 → **自动升级为按 QQ 号永久封禁**，openid 记录清除；
- 拦截优先级：全局按号 > openid 兜底 > 本群。

### 审计

授权 / 封禁 / 解绑 / 重载配置等关键操作全部写入 `data.json` 的 `audit` 环形缓冲
（保留最近 200 条），超管及以上发 **`审计日志 [条数]`** 回看：时间、操作、操作人、对象、详情。

### 常用命令

```

## 身份体系：QQ 号只是内部主键，**你不需要知道用户的 QQ 号**

**为什么有绑定这回事**：QQ 官方机器人开放平台**永远不会下发真实 QQ 号**——事件体与
OpenAPI 里只有 `openid` / `member_openid` / `union_openid`（官方「唯一身份机制」文档：
不同 bot 的 openid 不同，**同一人在不同群的 member_openid 也不同**）。

所以机器人用「QQ 号」当内部主键，让同一个人在各个群能被认出是同一个人
（积分、KunClient 账号、群管理员身份全部跨群通用——旧版本按 openid 存，
换个群就「变成另一个人」）。

### 👉 管理时你完全不用查 QQ 号

命令目标随便怎么写，**机器人自己去绑定表里把昵称/@人 换成 QQ 号**：

| 你发的 | 机器人做的 |
|---|---|
| `拉黑 @某人` / `拉黑 昵称` | 认人 → 封本群 |
| `封号 @某人` / `封号 昵称` / `拉黑 全 @某人` | 认人 → 查出他的 QQ 号 → 封所有群+私聊 |
| `封号 12345678 刷广告` | 你知道号就直接填 |
| `拉黑列表` | 同时列出本群 + 全局黑名单，**显示昵称不是加密 ID** |

> ⚠️ **唯一的例外**：对方**从没发过 `绑定QQ`** 时，平台给的是「每群一个」的加密 ID。
> 这时机器人会先做 openid 兜底全局拦截 + 封本群，并提示你：让他补发一次 `绑定QQ`，
> 或你用 `设QQ号 <QQ号> @某人` 直接登记——两者都会让拦截**自动升级为按号永久生效**。

### 绑定是**可选**的，不绑也能正常用

| 命令 | 说明 |
|---|---|
| `绑定QQ <QQ号>` | 可选。绑了跨群通用；不绑一切照旧（签到、kun 都不受影响） |
| `我的QQ号` | 看自己绑没绑 |
| `绑定表` / `解绑QQ <QQ号>` / `关联身份 <QQ号> @某人` | super 及以上维护用（解绑后可重新绑定，数据保留） |

绑定是**一号一绑、锁定不可改绑**，防止冒领他人 QQ 号、也防止被封后换号重绑绕过。

### 群管理平台接口（需机器人在群内是管理员）

官方 2026-08-10、09-03 两批开放了群聊管理接口，本机器人已全部接上。
**注意是「机器人在群里是管理员」，不是「你是管理员」** —— 发 `群信息` 可自检。

| 命令 | 说明 |
|---|---|
| `群成员` | 名册（编号 / 昵称 / 身份 / QQ）。**编号是禁言、撤回、移除的目标来源** |
| `撤回` / `撤回 3` | 撤回机器人自己最近 1~5 条回复 |
| `撤回 #3` / `撤回 昵称` | 撤回该成员最近一条 @ 机器人的消息（需机器人是管理员） |
| `禁言 3 10分` / `禁言 甲 乙 1小时` | 成员禁言，默认 10 分钟，**平台上限 30 天**；也接受昵称 / QQ号 / openid |
| `解除禁言 3` / `禁言列表` | 解除禁言 / 查看全员禁言模式与被禁言名单 |
| `移除成员 甲 乙 [拉黑]` | 批量移出群聊（单次 20 人，平台内邀能力） |
| `入群申请 [页数]` | 拉取待审批申请（昵称、来源、验证消息、问答、风险提示） |
| `入群同意 1 2 3` / `入群拒绝 2 广告号 拉黑` | 按序号批量审批；拒绝可带理由、可同时拉黑 |
| `自动审批` / `自动审批 执行 1` | 入群自动审批策略（机器人级，super 及以上）；执行 = 全量扫描白名单自动通过，约 10 分钟，需回「确认」 |

几个必须知道的平台限制：

- **撤回只有 2 分钟窗口**（超时报 `40064004`）。消息 ID 只在事件/发送响应里出现一次，
  所以机器人用内存台账记最近 40 条/群 —— 进程重启后台账清空（2 分钟窗口本来也用不上）。
- **禁言只能作用于普通成员**：群主、管理员、机器人都不行（`40062003`）。
- **移除成员 / 群成员列表是内邀能力**：没开白名单会提示「应用无接口访问权限」（`11253`）。
- 这些接口都按 **member_openid** 操作，不是 QQ 号。
- 🔴 **群消息事件拿不到「@ 了谁」**（2026-10-17 用 79 条线上原始事件核实）：事件体里
  **没有 `mentions` 字段**，`content` 里被 @ 的昵称会被整段抹掉只剩空格。所以
  「`禁言 @某人`」在群聊里**永远解析不出目标**。唯一可行的目标来源是**群名册** ——
  谁 @ 过机器人一次，谁的 `openid` 就从 `author.id` 落进 `roster`（`data.json`）。
  为此加了 `群成员` 命令列编号，`禁言 3 10分` 按编号操作；昵称 / QQ号 / 裸 openid 也能用。
  QQ 号走全局绑定表 `qq_bind`（跨群/私聊），所以「在别的群绑过 QQ」的人这里也能按号找到 ——
  实测同一个人的 `member_openid` **不随群变化**，跨群复用是安全的。
  平台也没有「群成员列表」接口（`/members` 报 `11253`），无法预先拉全量成员。
- 撤回/禁言/移除/审批全部过目标保护（不能对主人或权限 >= 自己的成员操作）并落审计。

### 菜单与指令面板

| 文件 | 平台接口 | 说明 |
|---|---|---|
| `menu.json` | `PUT /v2/menu` | 单聊（C2C）自定义菜单：最多 10 项，支持 `send_message` / `link` / `switch` / `menu` 折叠子菜单（子菜单最多 5 项，不支持再嵌套） |
| `panels.json` | `POST/PUT /v2/panels` | 指令面板：`group`（群聊）+ `c2c`（单聊），最多 20 项/面板；`only_admin: true` 的项只有群管理员能点 |

当前布局（顶层只有 4 个按钮，低频项收进折叠）：

```
签到
我的 ▾     我的账号 / 绑定邮箱 / 我的积分 / 积分排行
帮助
官网       https://kunawa.cn
```

- 启动和「重载配置」都会自动同步；手动重推：`菜单同步`，查看现状：`菜单查看`。
- 🔴 **`/v2/menu` 只作用于单聊**（文档原文：「仅支持 C2C（单聊）场景，设置后对所有用户生效」）。
  所以群管理类入口一律不放在菜单里 —— 群里看到的是 `panels.json` 的 `group` 面板。
  早先菜单里有个「群管」项，私聊点进去什么都干不了，已删除。
- 🔴 **面板 `type=command` 的 `name` 会被原样填进输入框**，所以它必须是**已注册的命令本身**
  （可写别名），不能写展示名。写「每日签到」用户点完发出去就是「没有这个命令」。
  展示用的说明放 `desc`（≤30 字符≈15 汉字）。
- 面板用 `panel.remark` 当**幂等键**：平台已有同 remark 的同场景面板就覆盖更新，没有才创建
  —— 否则每次重启都会堆出一个重复面板（上限 20 个）。
- 🔴 **推送前本地校验**（`core/menu.py`）：字符宽度（汉字算 2）、数量上限、类型枚举、
  `https://` 前缀、面板命令名是否存在。平台超限只回一个 `40030013`，不说哪一项超了。
  校验不过**不推送**，线上保持原样，日志里逐条列出错在哪。
- **内容与线上一致就跳过**（先 `GET /v2/menu` 深比较，剥掉平台回填的 `icon`），
  既不浪费 5 QPM，也不会让 `version` 每次重启白涨。
- `menu.json` 仍兼容旧格式（`{"content": {...}}` → `PUT /users/@me/menus`），老文件不用改。
- 自测：`py main.py --menutest`（结构合规 + 校验器反证，全离线）。

```

⚠️ **`config.json` 含 AppSecret，已加入 .gitignore，请勿外传、勿提交到公开仓库。**

`openid` 只保留在 `qq_bind` / `roster` / `identity_ban` 这三张「平台观测表」里，用于把平台事件

`data.json` 与 `backups/` 下都保留原有备份。

## 官方平台能力限制（重要，非机器人故障）

1. **只能被动回复**：群内必须 @机器人；每条收到的消息（msg_id）最多回复 **5 条**，超时回复会失败。
2. **主动消息需单独开通**：进群欢迎语属于主动消息，未开通权限时发送会失败（仅记录日志）。
3. **群管理接口要机器人是管理员**：撤回/禁言/入群审批都要求机器人在群内为管理员（`40062003`）；
   撤回仅 2 分钟窗口；禁言只能对普通成员、最长 30 天；「移除成员 / 群成员列表」仍是内邀能力（`11253`）。
4. **不下发真实 QQ 号**：只有 openid / member_openid / union_openid，QQ 号需用户自报一次。
   群管理接口因此按 openid 操作（封号仍走机器人的 QQ 号身份层）。
5. Markdown / 按钮消息需审核权限，本机器人使用纯文本，不受影响。

## 常见问题

- **群里发命令没反应**：确认 @ 了机器人；确认已开通「群聊」能力并已进群；看 `bot.log`。
- **撤回提示「已超过 2 分钟」**：平台硬限制，撤回窗口只有 2 分钟，无法绕过。
- **`禁言 @某人` 说「没找到这个人」**：不是 bug，是平台不给。群消息事件体里没有 `mentions`，
  被 @ 的昵称会被抹成空格，机器人拿不到对方 openid。改用：`群成员` 看编号 → `禁言 3 10分`；
  或直接 `禁言 <QQ号>`（对方绑过 QQ 即可）；名册里没有他又不知道 QQ，就让他在群里 @ 机器人
  随便发一句（`签到` 也算），进了名册就能管。
- **撤回/禁言提示「无操作权限」**：机器人不是群管理员 —— 发 `群信息` 看它当前身份，让群主设成管理员。
- **移除成员提示「应用无接口访问权限」**：该接口是平台内邀能力（11253），需要在开放平台申请白名单。
- **命令提示「需要 XX 权限」**：发「角色」看自己的身份；授权找主人（`超管添加`）或超管（`设置管理`）。
- **封号说「openid 兜底拦截」**：对方没绑过 QQ 号，已先做全局兜底拦截；让他发一次「绑定QQ」
  或用「设QQ号 <QQ号> @某人」登记，拦截自动升级为按号永久封。
- **回复失败/超时**：被动回复有 msg_id 有效期与 5 条上限，重新 @机器人 发一次即可。
- **断网恢复**：网关断线自动重连（优先 Resume 补发漏掉的事件），无需人工干预。
- **改了 config.json / data.json 不生效**：发「重载配置」（在线重读）；手工改过 data.json 用
  「重载配置 --磁盘」以磁盘为准，防止内存旧快照覆盖回去。
